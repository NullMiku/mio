# M19d Runtime Admission Controller

独立工作树：`/Volumes/Sector0/AppData/Mio/mio-wt-m19d`，分支
`EXP/m19d-admission`。冻结基线为 `a96d83ca0ee30239026b9ba27d5a5d547349f647`。
初始化时原仓库实际 clean，M19c 已提交；442 个文件逐项 SHA256 与 Race
工作树冻结清单一致。没有重新打包旧的 M19c 变化。

实现位于 `bunko/kiso/runtime/admission/admission.mio`。这是同一份可由 Go VM、
Go AOT 和纯 Mio AOT 执行的 Mio 状态机，单线程事件循环拥有者调用。
四类逻辑队列按 5:3:1:1 加权公平分配，支持空闲额度借用、全局与分类上限、
有界排队、20ms 或更短请求/分类截止时间、取消和执行完成确认、重复释放防护。
并发预算取延迟反馈、内存预算、配置和压力恢复上限的最小值。

Critical 立即停止新额度，已有任务继续；安全 Normal 输入允许一个探测额度，
连续稳定约 3 秒后每秒最多增加健康额度的 5%（整数最少一个），不补发积累步数。
Elevated 停止扩张，High 逐步缩减，重新 Critical 立即归零。
控制器不改写 M19c 压力等级，也不因预测 reason=4 永久锁住自身恢复状态。
运行中取消/超时仍计入并发和估算内存，只有执行器真正结束才释放额度；
释放额度不减少 GC 快照中的使用量。

## 能力与边界

| 项目 | 状态与范围 |
| --- | --- |
| Native 决策核心 | 实际 ARM64 镜像执行，两套 emitter，同一套状态机 |
| 压力输入 | `observe_words` 接受 M19c 八字复制快照；同线程、GC 外调用 |
| 自动快照采集桥接 | 尚未安装语言级访问器；未来 Runtime/Scheduler 负责读取并传入 |
| 时钟与延迟 | 可注入单调毫秒时钟、测量值反馈；测试是确定性输入，不声称真实 p99 |
| 任务执行、根拥有权 | 未来 Scheduler 负责；控制器仅保存整数 ticket 和资源估计 |
| HTTP、线程池、并发 Old GC | 本阶段未实现 |
| 跨线程安全 | 不支持，未引入普通 sequence 的伪原子发布协议 |

API、统计字段、事件循环调用顺序和复杂度见模块内 `README.md`。
公平性依赖已运行任务最终完成或确认取消，不对无限运行任务进行抢占。
内存估计是保守接纳预算，不承诺任意任务分配绝不 OOM。
