# Windows AMD64 stage 3: what the compiler needs

Generated by `tests/windows-amd64/survey.py` from `mio disasm` of the Go-frontend Mochi of each program (reachability from
main through OpCall/OpFunction/OpClosure). Columns show the state of the scalar lowering (`kiso/aot/lowerwin`) and of the
heap-capable lowering (`kiso/aot/lowerwinrt`). "supported" means the opcode is lowered, not that every operand type is.

Not covered by this survey (the Go frontend cannot compile them): `selfhost/cli`, `selfhost/frontend`, `selfhost/pipeline`,
everything that imports `kiso/os`. Their needs are listed in the "Beyond the backend driver" section below.

## Beyond the backend driver (read from source, not generated)

`selfhost/cli/main.mio` and `selfhost/frontend` additionally use `kiso/os`: `argc/arg_size/arg_copy` (command line),
`env_size/env_copy` (MIO_BUNKO), `chmod`, `remove`, `rmdir`, `pid`, `real_path`, `spawn`/`exec` (run/test), `spawn_test`
(test runner), `monotonic_ms`, `stdin_ready/stdin_wait` (LSP). They also use directory iteration (`open_dir`, `dir_next`,
...), `stat` and `mkdir` from `kiso/fs`, and Linux-only paths: `/dev/stderr`, `/dev/stdout` (handled by the Windows
`rt.syscall` shim), `/proc/self` (host detection in `selfhost/pipeline/linux.mio` `host_target`), `/tmp/mio-run-<pid>`
(CLI `run`) and POSIX modes in `chmod(…, 448/493)`.

## Status of the Windows runtime (lowerwinrt)

| area | state |
|---|---|
| heap allocation (VirtualAlloc reserve 8 GiB, commit 16 MiB steps) | implemented; Windows run in CI |
| exact precise GC, frame descriptors | Linux collector ported unchanged; GC stress corpus in differential tests |
| strings, arrays, structs, enums, nullable, closures, maps, floats | ported; differential corpus (25 programs) vs Go VM |
| fs: open/read/write/close/file_status | implemented over rt.syscall (Win32 CreateFileW/ReadFile/WriteFile/CloseHandle, UTF-8 paths) |
| fs: stat, mkdir, directory iteration | NOT implemented: rt.syscall returns -ENOSYS (explicit I/O error) |
| os: exit | implemented |
| os: args, env, spawn/exec, spawn_test, pid, real_path, remove, rmdir, chmod, monotonic_ms, stdin | NOT implemented: call stops with "unsupported operation" |
| threads, TLS, concurrent GC | not enabled (no capability flag) |
| crash handling | no signal handler; a fault ends the process with the Windows exception code |
| unwind data | every Win64-boundary and program function is framed with UNWIND_INFO; ported Linux runtime routines (alloc, GC, objects, fs) carry none |
| stack | PE reserve 64 MiB; stack overflow is a process fault, not a Mio error |
