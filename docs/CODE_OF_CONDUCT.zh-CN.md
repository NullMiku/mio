# Mio 社区行为准则

Mio 欢迎不同经验和背景的人参与。报告 Bug、提出问题、修订文档、补充测试和贡献代码，都是有价值的参与方式。

我们不要求每个人在技术选择上保持一致，但希望讨论始终围绕方案及其影响展开，而不是对参与者作出人身评价。

## 我们期待的行为

- 可以直接、建设性地指出代码、设计、基准测试或决策中的问题，尽可能说明理由或提供证据。
- 尊重刚开始学习或尚不熟悉项目的人。基础问题也可以提出。
- 尊重他人的时间，不通过反复催促或骚扰要求他人立即处理。
- 愿意澄清误解，并认真考虑不同的技术思路。
- 对贡献者与维护者采用相同的基本尊重标准。

技术分歧、负面代码审查或不合并某个 PR，本身并不构成违反行为准则。

## 不接受的行为

- 骚扰、威胁、人身攻击或歧视性言论。
- 不受欢迎的性暗示或性骚扰。
- 未经许可公开他人的隐私信息。
- 冒充他人、恶意扰乱讨论、刷屏，或在被要求停止后继续进行不受欢迎的联系。
- 因他人善意举报问题而进行报复。

这些要求同样适用于维护者。

## 适用范围

本准则适用于 Mio 的 Issue、Pull Request、Discussions，以及被项目明确指定为官方渠道的交流空间。它不用于干涉与项目无关的私人生活或个人观点。

## 报告与处理

如果问题适合公开讨论，可以在仓库创建 Issue。**请勿在公开 Issue 中发布他人的隐私或敏感事件细节。**

如果需要向维护者私密报告社区行为问题，请在项目正式公布专用联系方式后使用该渠道：

**【私密社区联系渠道：sfnco.linklin@gmail.com】**

涉及 GitHub 平台规则的行为，也可以使用 GitHub 自身的举报功能。GitHub Private Vulnerability Reporting 专门用于软件安全漏洞，不用于社区行为投诉。

维护者会依据可取得的事实核实情况，并在适当时联系相关人员。敏感报告的共享范围会尽量限制在处理所必需的程度，但无法保证绝对保密。

根据行为的严重程度和具体情况，可采取提醒、警告、移除不当内容、限制参与或禁止进入项目交流空间等措施。若举报涉及维护者，应尽可能交由未涉事的维护者处理；无法回避利益冲突时，应向报告者说明。

具体的贡献流程、测试与 PR 规范见 [贡献指南](CONTRIBUTING.zh-CN.md)。
