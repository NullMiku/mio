# Mio コミュニティ行動規範

Mio は、経験や背景の異なる人々の参加を歓迎します。バグ報告、質問、文書の修正、テストの追加、コードへの貢献は、どれも大切な参加方法です。

技術的な選択について全員が同じ意見である必要はありません。ただし、議論の対象はアイデアとその影響であり、参加者個人の評価ではないことを期待します。

## 期待する行動

- コード、設計、ベンチマーク、判断に対して率直かつ建設的に意見を述べ、可能な限り理由や根拠を示す。
- 学習中の人やプロジェクトに詳しくない人を尊重する。基本的な質問も歓迎する。
- 他の人の時間を尊重し、繰り返し催促したり嫌がらせをしたりして即時の対応を強要しない。
- 誤解を解く努力をし、異なる技術的アプローチも検討する。
- コントリビューターとメンテナーに同じ基本的な敬意を払う。

意見の相違、否定的なコードレビュー、PR をマージしない判断そのものは、行動規範違反ではありません。

## 認められない行為

- ハラスメント、脅迫、個人攻撃、差別的な発言。
- 望まれない性的な言動やセクシュアルハラスメント。
- 本人の許可なく個人情報を公開する行為。
- なりすまし、悪意のある議論の妨害、スパム、停止を求められた後も続く望まれない接触。
- 善意で問題を報告した人への報復。

これらの基準はメンテナーにも適用されます。

## 適用範囲

本規範は Mio の Issues、Pull Requests、Discussions、およびプロジェクトが公式と明示した交流スペースに適用されます。プロジェクトと無関係な私生活や個人的な意見を取り締まるためのものではありません。

## 報告と対応

公開しても問題のない内容については、リポジトリの Issue を利用できます。**個人情報や機微な事件の詳細を公開 Issue に投稿しないでください。**

コミュニティでの行為に関する非公開の報告は、プロジェクトが専用の連絡先を公開した後、そちらへお願いします。

**【非公開のコミュニティ連絡先：sfnco.linklin@gmail.com】**

GitHub のプラットフォーム規則に関する問題には、GitHub 自身の通報機能も利用できます。GitHub Private Vulnerability Reporting はソフトウェアの脆弱性専用であり、コミュニティ行動規範に関する申し立てには使用しません。

メンテナーは把握できる事実を検討し、必要に応じて関係者に連絡します。機微な報告の共有は対応に必要な範囲にとどめるよう努めますが、絶対的な機密保持は保証できません。

状況や重大性に応じて、注意、警告、不適切な内容の削除、参加制限、プロジェクトの交流スペースからの禁止などを行うことがあります。メンテナー本人に関する報告は、可能な限り当事者でないメンテナーが扱います。それが不可能な場合は、利益相反について報告者に説明します。

コントリビューションの手順、テスト、PR の基準は [貢献ガイド](CONTRIBUTING.ja.md) を参照してください。
