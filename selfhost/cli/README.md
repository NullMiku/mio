# Pure Mio native CLI candidate

The CLI, frontend, in-process Native AOT backend, runtime generation, signing,
embedded Bunko, test runner and LSP service are implemented in Mio. Ordinary
compilation does not spawn another compiler, linker or signing tool.

`build` defaults to a signed ARM64 native executable. `--emit=mochi` retains IR
export; native source exports use v16 typed call metadata while the decoder keeps
v14/v15 compatibility. `exec` compiles Mochi to native code before execution.
`run` forwards program arguments and exit status. `disasm` uses the Mio decoder.

`check` uses shared semantic analysis. Source diagnostic controls are
`--format=human|short|json`, `--color=auto|always|never` and `--verbose`.
Human diagnostics include source locations/markers; JSON retains structured codes,
byte offsets and spans. NO_COLOR and CI/TERM policy apply to terminal colors.
Test-command diagnostics share color policy and retain their localized/report
schemas, regexp filtering, native image isolation and independent child limits.

Bunko resources contain exact source bytes, versions, lengths and SHA256 values,
generated by Mio. Empty MIO_BUNKO selects embedded resources; `--bunko-root`
provides an explicit nonempty disk override with no fallback on failure.

`lsp --stdio` implements lifecycle/framing, document overlays, diagnostics,
hover/definitions/references/symbols/completion/signatures, cooperative in-flight
cancellation and debounce. Embedded library locations are readable read-only
native materializations; existing edits and original client URIs are preserved.

This remains a development candidate until the entire GF3 frozen-source,
one-candidate regression and isolation gates actually pass. Historical test
results do not replace that final run. System codesign is limited to independent
verification and trusted development seed preparation; ordinary output signing
is Mio ad-hoc signing, without a notarization claim.
