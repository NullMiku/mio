# E3 — 普通 Mio 用户代码自动 TLS / Shadow Frame / Safepoint + 真实多线程 GC

**开始状态**：`IN_PROGRESS`。当前手工引导的真实堆接入已有 64 次测试，但普通用户函数自动插桩未完成。已通过的原生堆测试是有价值的局部证据，不足以给 E3 PASS。

## 第一步：编译器/Runtime 差距审计

1. 在当前源码中逐项追踪：线程入口→TLS context→Mutator registry→Shadow Frame→根可达性→每个 Safepoint→GC coordinator→真实 Minor/Major；标出仍仅用于测试、手工建立的路径。
2. 列出 Native lowering 对 `x24`、Shadow Frame 根地址、寄存器活值、局部变量指针、函数参数、闭包/返回值与 native call 的处理规则。CPU 寄存器约束只在 ARM64 Adapter 表达，Portable GC 只表达语义。
3. 明确所有根（global/stack/register spill/closure/cell/array/map/LOS/nullable/generic）的类型布局与生命期，并保存可复现最小示例。禁止保守扫描 int/float 位型。
4. 确认 E2 注册表、导入区与线程清理已足以支撑**正式用户程序**，如缺项，先补该项并复验，禁止强行跳到 E3。

## 第二步：生产自动插桩（必须实际修改纯 Mio 代码）

1. 普通 Mio 程序启动时自动附加 main 线程 context；合法 Mio 创建的每个工作线程在运行用户函数前建立独立 TLS Root context；不依赖测试程序手写 Root vector。
2. 由 Codegen/Lowering 在函数进入/正常退出/显式返回及支持的其他控制转移维护 Shadow Frame push/pop；递归、嵌套 closure、间接调用、调用约定和其他异常返回不得泄漏或漏根。
3. 函数有 GC 机会时，在调用、分配慢路径、可能长时间执行的循环回边等位置插入 Safepoint Poll；同步保证引用临时值/寄存器活值写入精确 Root 前不会暂停，不能在对象/GC metadata 非安全中间态进入 Safepoint。
4. 线程进入阻塞 OS 调用时，先完成所需 Root 发布和状态切换；返回时正确恢复，可在安全条件下处理 pending GC epoch。线程退出需配合 Registry 的最后读者安全摘除。
5. 统一处理同步 GC 入口和跨线程 GC 请求，使 Minor/Major 回收真实共享对象图，完整栈/全局 Root 全部覆盖。原来 STW 单线程程序保持语义和 ABI 兼容。

## 第三步：从“测试特制程序”切到“真实普通 Mio 程序”

构造至少两种普通用户 `.mio` 源码（无手动 Root 发布函数调用）:

- A/B 两线程共享 Young/Old/LOS，A 分配 B 持根，STW GC 期间保活、稳定地址、撤根后能够真正回收；证明不是仅同一线程引用。
- 非平凡函数调用链：递归、函数值、捕获闭包、Array/Map/Struct/Nullable/泛型、长循环，GCStress 下无 Root 泄漏或过早回收。
- thread 反复注册、阻塞、恢复、退出；GC request racing register/exit，不因为无同步 Root 链而触发 UAF 或死锁。
- 若现有用户级线程 API 尚未公开，提供仅用于**原生用户函数执行路径**的内部启动桥验证，但禁止将直接手工 root 测试伪装成自动代码生成的证明；在报告中明确未公开 API 的限制。

必须有可验证的可达性反例：释放所有根后被识别为不可达，通过元数据/计数/受控重用验证；**禁止解引用已释放对象**。
