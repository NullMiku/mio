# E4 — Target-neutral Concurrent Old Mark 与 SATB 双屏障

**前置门禁**：E3 G3.1～G3.7 全部 PASS，普通 Mio 用户程序自动 Root + safepoint 成熟。当前 E4 NOT_ACCEPTED；禁止用状态机的 mock 测试代替真实 GC。

## 1. 可移植 GC 路径

1. 将 Old 追踪、颜色、epoch、在途任务/工作队列、Init/Remark 和并发协调的**真实语义算法**放到 `bunko/kiso/runtime/gc/` 或现有等价 Target-neutral 模块；由 Mio 编译器的 RuntimeOp/target adapter 生成操作。禁止把 ARM64 旧 emitter 复制成一份新的 Darwin-only GC。
2. Darwin ARM64 实现线程/Atomic/OS 与编译器机器码层，保留不支持 target 明确拒绝。
3. 建立每个 Mutator、Collector 与阶段机同步的线性化时点。实际 Phase Idle→Init STW→ConcurrentMark→Remark STW→ReadyToSweep；失败/取消为 Abort，必须阻止不安全释放。

## 2. 写屏障与覆盖审计

- **SATB pre-write**：GC 标记活动时，在堆槽覆盖/指针更新之前记录旧指针，必要时检查类型/指针布局，严格保证发布顺序；在无指针数值槽上不触发伪扫描。
- 保留 **Old→Young post-write Remembered Set**，与 SATB 的执行顺序、并发发布、重新扫描明确协同；不能用一种屏障替代另一种。
- 审计每个产生引用的 store/alias 路径：结构体字段、Array/Map、Cell/Closure、全局值、nullable/泛型/enum、LOS、Runtime 内部指针与可能的批量/原子引用替换。产出表格 `write-site → barrier → test → status`。
- 反复写入相同 slot、删除旧引用、跨线程发布对象、Old→Young→Old、标记期间新分配/晋升，不能丢旧对象可达性。

## 3. 真正的并发进度

- Collector 独立线程扫描 Old，Mutator 在标记期间继续安全执行普通 Mio 程序（不是暂停状态）；保存真实同一 monotonic 时钟下重叠区间与对象图验证。
- SATB 队列的生产者/消费者、分段队列满时背压/补偿、在途任务计数、终止检测、循环 GC epoch，不允许在 `Remark` 前遗漏消息。
- Minor 若发生于 Old Mark 期间，必须遵循显式互斥/安全协作（可短暂停顿），不能并发无锁修改对象头、mark bits 或 Young/Old list。
- `Remark` 必须握手全部真实 Mutator、drain 所有 SATB 与 in-flight 发布、扫描最新 Root，然后才可决定对象死亡。
- 如果一致性协议失效，可以安全 Abort/回到短暂停顿 STW 兼容路径，但这种运行不计并发 Mark PASS；功能门禁仍 BLOCKED。

## 4. 压力与反例

覆盖多生产者、队列溢出、marker 退出、线程生命周期、GCStress/HardCap/OOM、精确 Root 伪指针与各种对象形态，使用可重放执行序列。禁止只通过「并发标记结束」日志判断真正追踪正确。
