# E6 — 最终全量验证、跨平台边界、源码级新固定点

**前置**：E3、E4、E5 必须在同一实际源树各自 PASS。E6 是最终源冻结 + 完整验收，不得为了快捷先合并历史不同源码的成功结果。

## 1. 冻结候选源码

- 完整记录 Git HEAD、branch、dirty/untracked、编译器核心、GC、CPU/OS adapter、Bunko、测试、CLI/LSP 的有序源码 Manifest/SHA256。
- 可信 GF4 Native Seed 与当前源码对应条件需重新复核；所有新构建与应用的签名、hash、target、机器码格式正确。
- 禁止在正式验收开始后偷偷编辑冻结源码；若发现 Bug，保留失败、修复后重建全新候选并重跑受影响全部门禁。

## 2. 必须执行的真实验收

1. E3 普通用户函数自动 Shadow/TLS/Safepoint + 多线程精确 Minor/Major 全部回归。
2. E4 真并发 Old Mark、SATB 所有写入点、溢出/Remark/终止及对抗回归。
3. E5 Concurrent Sweep/LOS/Allocator 线程安全、abort/shutdown/OOM、epoch/quarantine。
4. M19b/c correctness：Young/Old、对象级晋升、稳定地址、Remembered Set、Shadow Frame、LOS 128KiB、GCStress、HardCap、Pressure、NativeFS，完整内存指标准确性。
5. Bunko、Frontend/Codegen、统一 `mio` CLI、LSP（真实会话/取消/路径）、ARM64/Mach-O/签名/动态导入及运行时协议。
6. 历史 GF4 相关 11 个见证、独立原生程序、当前源码新 GC 对照；仅能在同源条件下认定新验收，不因旧 hash 相等而推断自举。
7. 多线程确定性调度回放 + 随机种子样本 + 有界长时间 stress、内存上限和 OS 故障注入。冻结预设样本数量和中止规则；不能为通过验收临时减少负载。
8. 并发八字段 `memory.snapshot` 的一致性、seq、压力 Unknown 与 epoch；禁止只使用旧单线程 seqlock 约定无原子发布。
9. CPU/OS/platform contract 审计：Darwin ARM64 原生实机验收，Linux/AMD64/Windows 未实现的接口准确 `NOT_IMPLEMENTED`；无隐藏 Go/C/Python 编译或 GC 生产阶段。

## 3. 完整原生源码自举

对最终**同一份冻结源码**执行真正的：`Seed → A → B → C → D`。

每代从完整 `.mio` 编译器源码编译下一代的独立 `mio`，并实际执行必要代际及测试。比较 B/C/D 的 **全部原始未签名字节**（严格相等）；签名后整个 Mach-O 文件亦必须严格相等。新 GC 产生新 hash 是允许的；不能沿用旧固定点代替新验证。

所有阶段需保存 source/seed provenance、SHA256、签名检查、native 产物、实际命令/退出码/CPU/RSS/耗时，以及最后来源没变化的证明。不要在 E6 期间跑另一个 Worktree 的重型任务。

## 4. 指标/报告与签字

统计 Minor/Old Mark/Sweep 次数、GC pause、主/子线程停顿、标记/清除并发区间、Mutator 进度、SATB queue 和溢出、LOS reclaim/munmap、对象晋升、Heap/HardCap/pressure、dead/live 状态；性能 p50/p95/p99 若样本不够必须写 N/A，不得伪造改善率。

输出 `E6_FINAL_REPORT.md`，含 G6.1～G6.9 的证据链接/完整源 hash，以及 M19e `PASS` 或 `NOT_ACCEPTED` 的严格理由。对 GF5、v2.1.0 的发布状态单独声明，不自动 Commit、Push、Tag、Release。

**只有新源原生自举固定点、全部 E3/E4/E5 与 E6 真实 Gate 都通过，才允许宣布 M19e PASS。**
