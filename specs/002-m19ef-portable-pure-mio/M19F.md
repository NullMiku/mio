# 五、M19f — Adaptive GC Profiles 实施任务

依赖 M19e PASS（或架构/测试上真正无冲突时在独立工作树提前开发策略模型）。所有策略写在**纯 Mio** portable core，使用同一 Collector；OS 压力信号仅作为 Optional 输入。

## F0：明确 profile 语义与配置

- `High`：在允许的堆预算范围内优先吞吐、较低 GC 频率、更积极地利用后台 worker 和批次，接受较高内存与部分暂停成本。
- `Balanced`：默认稳定折中，受内存压力约束、控制平均吞吐和延迟；不作偏执优化。
- `Low`：优先低尾延迟（p95/p99）和高并发服务；**不是最小 RSS**，不得无界扩大 heap，也不保证零 STW。
- 显式 heap cap > profile 优化目标；所有模式同样守住内存安全、GC 精确性和 OOM 协议。
- CLI 若提供 `--gc=high|balanced|low`，须检查版本与现有 `mio build` 参数；新增开关需有帮助/验证/默认/无效值报错和嵌入生成程序的确定性元数据。当前并非已实现功能。

## F1：纯 Mio policy 模型

- 将旧的 `memory_policy.mio` Go-generated policy 重建为**可在 Mio 中维护**的 portable policy 状态机或 target-neutral runtime-op emitter，Go 不再是官方更新工具。
- 输入：occupied/committed/goal/hardcap、Young survival、promotion rate、Old bytes、LOS、allocation throughput、concurrent debt、mark/sweep progress、最近 Minor/Major STW 延迟分布、系统 pressure optional。
- 输出：GC kick/Young goal/Old cycle start/worker budget/sweep debt/promotion threshold (2–8，先按既有边界核实)/heap growth。所有决策 deterministic、饱和运算、溢出安全、阈值迟滞、开销上界。
- Profile 切换（如支持运行时切换）必须在 safepoint 或原子发布路径处理，不能改变对象布局/旧字段的解释。
- `Normal/Elevated/High/Critical` 保留。Critical 快速升档、下降多次稳定采样；存在 high alloc-rate 但高有效回收的场景不得长期错误维持 Critical。

## F2：Pressure / Admission 与 GC 职责隔离

- GC 发布 pressure snapshot/telemetry，由外部 Admission Controller 选择是否限流。M19d 仍属于独立可合入组件；不得把 HTTP 503 / 请求队列编码进 GC。
- 支持平台 pressure unknown；没有专用 OS 观测时使用 heap/GC 近似并标注来源。
- Snapshot 的原子一致性继承 M19e 正式协议；采样本身不能造成不可控 STW 或递归分配。

## F3：压力模型/调优验证

最少建立四类 workload：

1. High：纯数学/数值数组，测吞吐、GC CPU、对象占用；不可把算术溢出或数值误判为 pointer。
2. Balanced：混合短命/长命对象、LOS、跨代指针。
3. Low：高并发小请求模型，测每请求延迟 p50/p95/p99、Minor/Remark 暂停和吞吐。
4. Pressure：硬 cap、突增分配、可回收 burst、持续 Old 背景回收、压力输入缺失/波动/恢复。

- 使用同一来源、同一机器、相同负载种子、热身与重复样本，报告 wall/CPU/RSS、pause histogram、GC 次数、回收效率；不要用单次数据虚称胜过 Go/Rust。
- 测试必须实际证明三种 profile 产生不同、符合预期而受限制的策略决策，且都能通过同一精确根/类型语义测试。
- High 在 throughput workload 上以吞吐为主要优化方向；Low 在 latency workload 上以 p99 为主要优化方向。结果与噪声范围不吻合则继续调优/标记性能门禁未通过，不通过降低正确性换成绩。

## F4：最终冻结与 Native 自举

- 同源码验证 M19e 仍 PASS、M19b/c 重要回归、Full selfhost fixed point；并根据目标记录跨 CPU/OS 后端合同测试。
- 确认新的 profile/metaslot 不改变 `mio` 从自身完整源码重新构建自身的确定性；资源/seed 改变时保留新版 provenance。
- 文档与 CLI 显式标注平台支持状态，不把 Darwin ARM64 的 Pass 冒充 Linux/Windows Pass。

**M19f PASS** 由完整正确性与有统计意义的策略调优结果共同决定。
