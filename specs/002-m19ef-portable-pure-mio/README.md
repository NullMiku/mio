# M19e + M19f — Portable Pure-Mio GC (v0.1)

**状态：实施规范 / 非验收报告**。基于截至 2026-10-27 已查验的 `mio-kobo/mio` `Mio-2.1` 分支；当时 HEAD `f8410f48ee69eb2bcd228eafe423b92fc1dd7d2f`。在执行时重新核查 HEAD、工作树、已接受的 GF5/M19 证据与现有 API；不要把这一 SHA 当作永久当前状态。

**目标**：在保留 M19b/M19c 的非移动式分代 GC 基础上，以 **纯 Mio** 实现真正并发的 Old GC（M19e）和 High / Balanced / Low 运行时策略（M19f），且 GC 算法/策略不依赖 Darwin、Linux、Windows 或 ARM64、x86-64。首个实测后端仍可为 `darwin-arm64`，但所有 OS/CPU 差异必须封装在可替换后端。

**不是**重新开发 GC，也不是现在承诺已完成其他操作系统。没有实际机器/CI 的后端均标记 NOT_IMPLEMENTED / NOT_RUN。

## 关键背景

现有 `bunko/kiso/aot/lower/generational.mio` 和 `large_objects.mio` 是纯 Mio 编写，但函数参数直接为 `arm64.Assembler`，**源码实现语言纯 Mio ≠ GC 核心架构已跨 CPU**。现有 `memory_policy.mio` 仍带「generated by go run」标记与 ARM64 指令常量，后续修改不得要求运行 Go 生成器。现有 `memory.snapshot` 的偶/奇 sequence 尚不构成并发同步协议。

当前 `selfhost/pipeline/compiler.mio` 的默认目标是 Mach-O / ARM64；M19ef 应创建跨平台 *GC 架构*，而不是越权实现所有二进制格式。任何新增目标编译路径须显式检查后端能力；不允许 silent fallback。

## 使用

将 `specs/002-m19ef-portable-pure-mio/` 放在 Mio 仓库根目录的 `specs/` 下。在目标 `Mio-2.1` 的独立 worktree 中阅读 `CODEX_START.txt` 并执行；Codex 不得触碰用户其他 worktree，未经授权不 Commit/Push/Tag/Release。
