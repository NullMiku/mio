# 四、M19e — Concurrent Old Mark-Sweep 实施任务

Codex 每完成一关，需产生纯 Mio 源码、可实际执行的 native tests、源快照 SHA256、命令/exit、失败样例和一份机器可读结果。不可把设计通过当作实现通过。

## E0：冻结/兼容合同

- 从 `Mio-2.1` 的独立 Worktree 审计并冻结 M19b/c、GF4/GF5 当前可信 native seed 与最新状态；逐项定位 header bits、side table、young links、remembered set、LOS、shadow frames、root scan、memory state slots。
- 建立「对象状态 / metadata 偏移 / 调用约定 / 根集合 / 既有测试」矩阵，先写最小失败用例/对照测试；不改已冻结 GF5 工作树。
- 识别目前 `generational.mio`/`memory_policy.mio` 对 ARM64、Darwin 和 Go generator 的真实耦合；每条指出去留及目标后端接口。`E0 PASS` 仅代表审计基线。

## E1：Pure-Mio Runtime contract

- 新建 target-neutral `gc` / runtime operation API 和独立 target descriptor/feature gate；不得在 portable core 导入 ARM64/Mach-O。
- 增加纯 Mio `RuntimeOp` 或等价结构以表达 AtomicLoad/Store/CAS/RMW/Fence、ThreadStart/Join、Park/Wake、Reserve/Commit/Release、Clock、Pressure、Roots。
- 构建 mock emitter/contract tests；Darwin ARM64 adapter 延续已有生成器，后端未支持时明确错误。
- 不强迫 Mio 新增 trait 语法；现有 `kata`/`sentaku`、普通函数足够时优先使用。

## E2：Darwin ARM64 首个原生同步/线程后端

- 由纯 Mio 编写 AArch64 原子指令编码（包括必须的 Acquire/Release/CAS/循环/栅栏）和单元测试，对比机器码编码器已支持指令的字面结果；检查失败时的循环进展保证。
- 通过 OS public ABI 提供 GC worker、TLS/thread registry、等待/唤醒；若需要动态链接 libSystem 等系统库，实现并测试恰当 Mach-O/ABI bridge，不允许借助 C 代码生成目标程序。
- 先完成非 GC 并发 smoke：两个线程读写一个共享 64 位状态，重复验证内存序、可见性、join、线程资源释放；有故障可复现。直到这一关 PASS，不修改 Old mark 主算法。

## E3：多线程精确 Root 与 Safepoint

- 每线程独立 Shadow Frame 链；线程注册/退出、blocked/native-call 模式、TLS 和 GC handshakes，避免随意暂停后保守扫描。
- 在 allocation、函数调用/返回、循环回边及必要热点插入安全点，定义超时/非响应线程策略。GC Root 管理不能依靠扫描 C/Go runtime stack。
- 线程间分享 Closure/Cell/Map/array/LOS 对象时，Root 和写入顺序必须证明。
- 确认无 GC 线程介入时与现有程序/ABI 兼容。

## E4：Concurrent mark 与双写屏障

- 添加 SATB pre-write、现有 Old→Young post-write 联合协议；列出所有 pointer store callsites，并以静态审计检查覆盖，特别是 global、closure cell、map、数组、struct、LOS。
- 标记队列并发安全、overflow 不丢项；Init/Remark STW 完整握手、对象出生与晋升颜色安全。
- 造原生竞态样例：黑→白边、Old→Young→Old、同一 slot 频繁覆写、mutator 新增/退出、队列满、GCStress、GC 中分配、误判整数地址、LOS。

## E5：Concurrent sweep、释放安全与中止

- 并发 Sweep 阶段必须与 mutator 并存，管理 free-bin/side metadata、LOS unlink/munmap、allocator 的 epoch/quarantine；既有 LOS 8 次 munmap 边界需要明确在多线程下的释放协议。
- worker 出错、heap cap、OOM、GC 重新入/重启、程序退出阶段须安全释放，避免 double free / lost mark / ABA。
- 实际测量 mutator 与 GC worker 时间窗口有交集；不能使用仅 GC 在单独线程而 mutator 全程暂停的伪并发。

## E6：真实回归、兼容与自举

- 同源码构建原生 Mio，M19b/c 全部关键正确性与内存压力回归（通过的历史 Race 记录独立留存）。
- 真正并发 stress（数千轮线程交错、不同堆上限、重入/取消、LOS/细粒度对象混合、跨线程 Root），超时不能判 PASS。
- 证明输出地址稳定、无漏回收/错回收、memory.snapshot 一致读取、pause metrics 符合记录。
- 重验完整原生源码级自举（Seed→A→B→C→D，固定点与每代运行实际证明），记录 unsigned 与 signed 对照、B=C=D；当前 GF4 的旧 SHA 不一定保持相同，但新固定点必须稳定。

**M19e PASS 附加条件**：由 target-neutral GC 核心 + darwin-arm64 adapter 真实运作；其他平台 NOT_IMPLEMENTED 均明确。真实多线程安全性问题未证明时不得 PASS。
