## 正式产品的实现与依赖

Mio 必须成为由自身语言实现的统一原生编程语言工具链，禁止用混合语言架构完成正式产品。

所有正式编译器组件、CLI、Frontend、IR、Backend、Runtime/GC 生成逻辑、标准库、测试运行器及工具链服务，必须使用 Mio 实现，并由 Mio Native AOT 编译。所有用户命令共用同一套原生编译核心，禁止 Go VM、其他语言编译阶段、隐藏 fallback，以及以跨语言桥接长期替代未实现功能。

正常源码编译、执行、自举、离线安装和发行构建，不得依赖 Go、Python、C、Clang、LLVM 或其他外部语言工具链。允许操作系统 syscall、ABI、必要系统库和可信的初始原生 Mio Seed。

历史参考实现及辅助验证工具可保留在隔离测试/审计环境中；其进程、产物与依赖不得进入正式编译、打包、发行或自举链。当前 Python 探测脚本与 Go 参考程序仅作为 GF1 开发差分证据，不能作为最终交付的构建入口、种子代际或正式验收替代。

CI runner 可以启动 `mio`；正式构建、测试运行、资源生成、签名生成、打包、哈希和来源清单生成逻辑必须由 Mio Native 提供。系统验签及外部来源核查属于隔离辅助审计，不代替原生实现。

## 各阶段新增硬门禁

- GF1：前端及语义修复以 Mio 源码实现，原生执行验证；保留既有功能与正确性。参考工具只用于开发定位。
- GF2：前后端与 IR 在单个 Mio 原生进程内运行，源码到独立原生产物不经过任何其他语言阶段。
- GF3：所有公开命令、标准库、Runtime/GC 生成、CLI、测试运行器、LSP 等服务均为 Mio Native；不能将参考工具打包、嵌入或隐藏调用。
- GF4：完整 `.mio` 源码在隔离环境完成可信 Mio Seed → A → B → C → D；禁止其他语言生成步骤，包括每代先用 Go 产生 IR。保留完整未签名 B=C=D 字节和执行来源证明。
- GF5：正式构建与发行候选不能依赖 Python/Go/C 等。移除外部验证环境后仍能由原生 Mio 完成构建、测试、打包及离线安装。外部审计记录单独标明，不参与正式产物来源。

任一阶段不得通过删除已有功能、降低语义正确性、关闭 GC/指针检查、缩小固定语料、跳过验收或改变失败期待获得 PASS。

## 最终强制证明

1. 只有一个 `mio` 原生工具链可执行文件。
2. 核心及全部正式功能均有可追溯的 Mio 源码，并由 Mio Native AOT 构建。
3. 完整 `.mio` 源码能够编译成独立原生程序。
4. 不依赖 Go VM 或其他语言实现的编译阶段。
5. 隔离环境中的完整纯 Mio 多代源码自举实际执行成功。
6. GF1～GF5 全部语义、GC、兼容性、原生验收及 A1～A12 在最终源码清单上实际通过。

最终 A1～A12 的 PASS 必须附正式依赖闭包和隔离构建轨迹，区分“产品来源证明”与“参考验证结果”。外部工具不在 PATH 不是充分证明。
